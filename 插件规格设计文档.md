# WinScript Support 插件规格设计文档

WinScript Support 是一个面向 IntelliJ 平台的 Windows 脚本支持插件，目标是让 Batch（`.bat` / `.cmd`）与 PowerShell（`.ps1`）在 IDE 中获得开箱即用的基础编辑与执行体验。本文档定义其 v1.0（MVP）的产品范围、功能规格、技术架构、模块划分与里程碑，作为开发启动前的决策基线。

## 文档信息

- 文档版本：v0.1（设计稿）
- 目标 IDE：IntelliJ IDEA Community Edition / 统一免费版（2025.3+）
- 目标语言：Batch（`.bat` / `.cmd`）+ PowerShell（`.ps1`）
- 开发语言：Java 为主，Kotlin 用于可选 UI 与工具模块

## 1. 产品定位与范围

### 1.1 一句话定位

WinScript Support 为 IntelliJ 平台提供 Windows 脚本的**开箱即用基础支持**：打开 `.bat` 或 `.ps1` 不再是一片灰色文本，而是有可读的高亮、可执行的 Run Configuration、以及可扩展的架构留白。

### 1.2 版本范围划分

| 能力                     | v1.0（MVP）                                | v1.x（增强）             | v2.0（远期）                         |
|--------------------------|--------------------------------------------|--------------------------|--------------------------------------|
| Batch 语法高亮           | ✅ 自研 Lexer                              | 完善高亮粒度、配色方案   | —                                    |
| PowerShell 语法高亮      | ✅ 自研轻量 Lexer                          | 借助 PSES 做语义级高亮   | —                                    |
| 运行配置（Batch）        | ✅ 支持脚本路径、参数、工作目录            | 环境变量、宏替换         | —                                    |
| 运行配置（PowerShell）   | ✅ 基础执行（`pwsh` / `powershell.exe`）   | 编码设置、执行策略感知   | —                                    |
| 空运行配置               | ✅ 执行任意命令                            | —                        | —                                    |
| PowerShell 代码补全      | ❌                                         | 通过 PSES LSP 接入       | 完整语义补全                         |
| PowerShell 调试          | ❌                                         | —                        | DAP 接入（PSES Debugging Service）   |
| Batch 调试               | ❌                                         | —                        | 不列入规划                           |

### 1.3 范围原则

v1.0 不追求与成熟的 `intellij-powershell` 正面竞争。它的补全和调试依赖 PowerShell Editor Services，工程量远超"基础支持"范畴。WinScript Support 的第一优先级是**让 Batch 和 PowerShell 都有一个可用的、不依赖外部服务的编辑器体验**，同时把 PowerShell 的深度能力作为清晰的架构预留。

## 2. 功能规格

### 2.1 编辑器基础能力

**Batch（`.bat` / `.cmd`）**

- 文件类型注册：扩展名 `.bat`、`.cmd`，默认关联到 `Batch` 语言。
- 词法高亮 Token 集（v1.0 最小集）：
  - 关键字：`if`、`else`、`for`、`goto`、`call`、`set`、`echo`、`exit`、`rem`、`::`
  - 变量引用：`%VAR%`、`%~dp0`、`%1`–`%9`、`!VAR!`（延迟展开）
  - 字符串与转义：`^` 转义、引号包裹
  - 标签与跳转目标：`:label`
  - 注释：`rem` 行、`::` 行
- 错误高亮（轻量）：未闭合的 `%`、未闭合的括号对（通过 Lexer 层标记 `BAD_CHARACTER`）。

**PowerShell（`.ps1`）**

- 文件类型注册：扩展名 `.ps1`，默认关联到 `PowerShell` 语言。
- 词法高亮 Token 集（v1.0）：
  - 关键字：`function`、`param`、`if`、`else`、`foreach`、`while`、`try`、`catch`、`throw`、`return`
  - 变量：`$var`、`$env:VAR`、`$script:var`、`${...}`
  - 字符串：单引号、双引号、here-string（`@"..."@`、`@'...'@`）
  - 注释：`#` 行注释、`<# ... #>` 块注释
  - 运算符与特殊 Token：`|`、`-eq`、`-like`、`-match`、`::`、`.`（dot-sourcing）

**共同行为**

- 配色方案遵循 IDE 默认主题，不强行覆盖用户自定义。
- 通过 `SyntaxHighlighterFactory` 注册高亮器，Lexer 支持增量重词法分析（`Lexer.getState()` 返回单一整数状态）。

### 2.2 运行配置

这是 v1.0 的核心执行能力。参考 `idea-batch` 的既有做法，提供三类运行配置：Batch 脚本、PowerShell 脚本，以及可执行任意命令的空配置。

**Batch Script Run Configuration**

| 配置项       | 说明                                                       |
|--------------|------------------------------------------------------------|
| 脚本路径     | 必填，支持项目内宏（`$ProjectFileDir$`、`$FileDir$` 等）   |
| 脚本参数     | 传递为 `%1`、`%2`…                                         |
| 工作目录     | 默认脚本所在目录，可覆盖                                   |
| 解释器       | 固定使用系统 `cmd.exe`（可通过设置覆盖路径）               |
| 控制台编码   | 默认系统编码，可配置（避免中文输出乱码）                   |

**PowerShell Script Run Configuration**

| 配置项     | 说明                                                                             |
|------------|----------------------------------------------------------------------------------|
| 脚本路径   | 必填，支持宏                                                                     |
| 脚本参数   | 以数组形式传递                                                                   |
| 工作目录   | 默认脚本所在目录                                                                 |
| 解释器     | `pwsh`（PowerShell 7+）优先，回退 `powershell.exe`；可在插件设置中指定完整路径   |
| 执行策略   | 可选：`Bypass` / `RemoteSigned` / 不干预（默认不干预，尊重系统策略）             |
| 终端编码   | 默认 UTF-8，可切换                                                               |

**空运行配置**

一种不绑定具体脚本文件的配置类型：用户只填写"命令行"字段，插件负责在指定工作目录中启动一个 Shell 进程执行它。用于调用外部工具或临时命令。

### 2.3 明确不在 v1.0 中的功能

以下功能不进入 v1.0，以避免范围蔓延：

- Batch 的 Go to Definition / Find Usages（`idea-batch` 的已有能力中提及，但需要 PSI 引用解析支持，工程量显著）。
- PowerShell 代码补全与语义检查（需要 PSES）。
- PowerShell 调试（需要 PSES Debugging Service 与 DAP）。
- 代码格式化 / 重构。

## 3. 技术架构

### 3.1 分层架构

```text
┌──────────────────────────────────────────┐
│ UI / Settings Layer                      │
│ Settings UI · Run Config UI Forms        │
├──────────────────────────────────────────┤
│ Execution Layer                          │
│ ConfigurationType · ConfigurationFactory │
│ ProgramRunner · CommandLine              │
├──────────────────────────────────────────┤
│ Language Infrastructure Layer            │
│ Language · FileType · Lexer              │
│ SyntaxHighlighter · Annotator            │
├──────────────────────────────────────────┤
│ IntelliJ Platform                        │
│ PSI · VirtualFile · ExecutionManager     │
└──────────────────────────────────────────┘
```

### 3.2 关键设计决策

**决策一：Batch 与 PowerShell 走不同的语法实现路线**

- **Batch**：完全自研 Lexer。Batch 语法相对简单，Token 集可控，JFlex 或手写 Lexer 足以覆盖 v1.0 需求。不引入 Parser 和完整 PSI，v1.0 的 PSI 仅保留文件级结构（`PsiFile` 即可），为后续按需扩展留出空间。
- **PowerShell**：自研轻量 Lexer 用于**词法高亮**，同时抽象出 `PowerShellLanguageServiceBridge` 接口。v1.0 该接口为 no-op；v1.x 接入 PSES 后，补全、检查等功能通过该 Bridge 注入，而不需要重写高亮层。PowerShell 官方已有成熟的 Editor Services 可供 LSP 客户端集成，IntelliJ 侧的多个 PowerShell 插件都走这条路。

**决策二：运行配置与语言支持解耦**

Batch 和 PowerShell 的运行配置共享一套执行骨架（`ConfigurationTypeBase` → `ConfigurationFactory` → `RunConfigurationBase` → `ProgramRunner` / `CommandLineState`），只在"如何构造命令行"和"UI 表单字段"上分叉。这避免了两套几乎相同的执行代码。

**决策三：不依赖 Ultimate 专有模块**

全部实现基于 `intellij-platform` 开源 API。`plugin.xml` 中不引入任何 Ultimate 专有依赖，确保 Community Edition / 统一免费版可完整运行。

## 4. 模块划分

| 模块                     | 语言     | 职责                                                               | 关键类 / 扩展点                                                                                    |
|--------------------------|----------|--------------------------------------------------------------------|----------------------------------------------------------------------------------------------------|
| `language-batch`         | Java     | Batch 语言定义、文件类型、Lexer、语法高亮                          | `BatchLanguage`, `BatchFileType`, `BatchLexer`, `BatchSyntaxHighlighterFactory`                    |
| `language-powershell`    | Java     | PowerShell 语言定义、文件类型、Lexer、语法高亮、PSES Bridge 接口   | `PowerShellLanguage`, `PowerShellFileType`, `PowerShellLexer`, `PowerShellLanguageServiceBridge`   |
| `execution-common`       | Java     | 运行配置共享骨架、宏解析、进程启动抽象                             | `ScriptRunConfigurationBase`, `ScriptCommandLineBuilder`, `ShellPathResolver`                      |
| `execution-batch`        | Java     | Batch 运行配置类型与 UI                                            | `BatchRunConfigurationType`, `BatchRunConfiguration`                                               |
| `execution-powershell`   | Java     | PowerShell 运行配置类型与 UI、解释器探测                           | `PowerShellRunConfigurationType`, `PowerShellRunConfiguration`, `PowerShellInterpreterDetector`    |
| `settings`               | Kotlin   | 插件全局设置（解释器路径、默认编码、执行策略）                     | `WinScriptSettings`（`applicationService`）、`WinScriptConfigurable`                               |
| `util`                   | Kotlin   | 通用工具（路径处理、文件扩展判断）                                 | 工具函数 / 扩展函数                                                                                |

## 5. 插件工程结构

基于 `intellij-platform-plugin-template` 初始化。第 4 节定义的模块边界在 v1.0 先以包结构落地（见下方目录树），待模块边界稳定后再拆分为独立的 Gradle 子模块：

```text
winscript-support/
├── build.gradle.kts
├── settings.gradle.kts
├── gradle.properties
├── src/
│   └── main/
│       ├── java/com/winscript/support/
│       │   ├── batch/
│       │   │   ├── BatchLanguage.java
│       │   │   ├── BatchFileType.java
│       │   │   ├── lexer/BatchLexer.java
│       │   │   └── highlight/BatchSyntaxHighlighterFactory.java
│       │   ├── powershell/
│       │   │   ├── PowerShellLanguage.java
│       │   │   ├── PowerShellFileType.java
│       │   │   ├── lexer/PowerShellLexer.java
│       │   │   ├── highlight/PowerShellSyntaxHighlighterFactory.java
│       │   │   └── service/PowerShellLanguageServiceBridge.java
│       │   ├── execution/
│       │   │   ├── common/ScriptRunConfigurationBase.java
│       │   │   ├── batch/BatchRunConfigurationType.java
│       │   │   └── powershell/PowerShellRunConfigurationType.java

│           └── META-INF/
```

### `plugin.xml` 最小扩展注册

```xml
<idea-plugin>
    <id>com.winscript.support</id>
    <name>WinScript Support</name>
    <version>0.1.0</version>
    <vendor>...</vendor>

    <depends>com.intellij.modules.platform</depends>

    <extensions defaultExtensionNs="com.intellij">
        <!-- 文件类型 -->
        <fileType name="Batch Script"
                  language="Batch"
                  implementationClass="com.winscript.support.batch.BatchFileType"
                  extensions="bat;cmd"/>
        <fileType name="PowerShell Script"
                  language="PowerShell"
                  implementationClass="com.winscript.support.powershell.PowerShellFileType"
                  extensions="ps1"/>

        <!-- 语法高亮 -->
        <lang.syntaxHighlighterFactory language="Batch"
            implementationClass="com.winscript.support.batch.highlight.BatchSyntaxHighlighterFactory"/>
        <lang.syntaxHighlighterFactory language="PowerShell"
            implementationClass="com.winscript.support.powershell.highlight.PowerShellSyntaxHighlighterFactory"/>

        <!-- 运行配置 -->
        <configurationType
            implementation="com.winscript.support.execution.batch.BatchRunConfigurationType"/>
        <configurationType
            implementation="com.winscript.support.execution.powershell.PowerShellRunConfigurationType"/>

        <!-- 全局设置 -->
        <applicationService
            serviceImplementation="com.winscript.support.settings.WinScriptSettings"/>
        <applicationConfigurable
            instance="com.winscript.support.settings.WinScriptConfigurable"
            id="com.winscript.support.settings"
            displayName="WinScript Support"/>
    </extensions>
</idea-plugin>
```

`plugin.xml` 的职责只有两个：身份与元数据，以及扩展/扩展点/服务/监听器的注册。所有实现类不应在 `plugin.xml` 中承担逻辑。

## 6. 运行配置技术规格

### 6.1 类关系

```text
ConfigurationTypeBase
  └── ScriptRunConfigurationType (abstract)
        ├── BatchRunConfigurationType
        └── PowerShellRunConfigurationType

RunConfigurationBase<ScriptRunConfigurationOptions>
  └── ScriptRunConfigurationBase (abstract)
        ├── BatchRunConfiguration
        └── PowerShellRunConfiguration

ProgramRunner<RunnerSettings>
  └── ScriptProgramRunner
```

`ScriptRunConfigurationBase` 提供：

- 脚本路径、参数、工作目录的 getter/setter 与宏解析。
- `getState(Executor, ExecutionEnvironment)` 的公共骨架。
- 抽象方法 `buildCommandLine()` 由子类实现具体命令行拼接。

### 6.2 进程启动路径

| 语言         | 命令构造                                                                                              |
|--------------|-------------------------------------------------------------------------------------------------------|
| Batch        | `cmd.exe /c "<scriptPath>" <args>`                                                                    |
| PowerShell   | `pwsh -NoLogo -NoProfile -File "<scriptPath>" <args>`（回退 `powershell.exe -NoProfile -File ...`）   |
| 空配置       | 用户填写的完整命令行，在指定 Shell 中执行                                                             |

执行通过 `ExecutionManager` 与 `CommandLineState` 完成，输出在 IDE 的 Run 工具窗口中呈现。

## 7. 兼容性与依赖

- **最低 IDE 版本**：2025.3（统一免费版边界），以利用稳定的平台 API 和免费版完整功能。
- **JDK**：17（与当前 IntelliJ Platform Gradle Plugin 默认一致）。
- **运行时依赖**：
  - v1.0：无外部运行时依赖。
  - v1.x（PowerShell 增强）：可选依赖 PowerShell Editor Services 二进制，通过插件设置配置路径，不捆绑进插件 JAR，以控制体积和许可证合规性。
- **插件许可证**：建议 Apache 2.0，与参考项目 `intellij-powershell` 保持一致，便于后续复用其开源组件（若采用）。

## 8. 里程碑建议

| 里程碑                      | 交付物                                                 | 验收标准                                                      |
|-----------------------------|--------------------------------------------------------|---------------------------------------------------------------|
| **M1 — 语言骨架**           | Batch/PowerShell 文件类型注册、Lexer、语法高亮         | 打开 `.bat`/`.ps1` 文件，关键字、变量、注释、字符串正确着色   |
| **M2 — 可执行**             | Batch/PowerShell/空运行配置，宏解析，输出到 Run 窗口   | 从编辑器右键或 Run 菜单可执行脚本，参数与工作目录生效         |
| **M3 — 设置与打磨**         | 全局设置 UI（解释器路径、编码、执行策略），错误高亮    | 用户可覆盖解释器路径；未闭合 `%` 等词法错误有提示             |
| **M4 — Marketplace 发布**   | 插件签名、描述、截图、兼容性声明                       | 可在 2025.3+ 免费版 IDEA 中安装运行                           |
| **v1.x 预留**               | `PowerShellLanguageServiceBridge` 接口稳定             | PSES 集成可在不改动 Lexer/高亮层的前提下接入                  |

## 9. 核心取舍

WinScript Support v1.0 的竞争力不在于"比现有插件功能多"，而在于**用一个插件同时覆盖 Batch 和 PowerShell 的基础编辑器体验与执行能力，且不强制用户安装外部服务**。Batch 侧参考 `idea-batch` 的轻量路线，PowerShell 侧在 v1.0 保持自包含、为 v1.x 的 LSP 深度集成留好接口。这既是对既有选型决策（Java 起步、Community 版、参考而非 Fork 现有项目）的延续，也是一个可以在合理周期内交付并发布的务实范围。
